# 工具首页与封面预览 实施计划

## 一、需求概述

把「启动即进入工作页」改为「启动进入工具首页」：

- 首页按分类（标签）分组，用封面卡片网格展示所有工具，风格接近 RunningHub 的应用/工作流搜索页。
- 点击封面卡片进入现有工作页；左侧工具列表继续保留，可直接切换工具。
- 顶栏提供「工具首页」入口，随时回到封面页重新挑选工具。
- 每个工具可上传一张封面图；封面存放于 `tools/` 目录，文件名与工具配置文件同名，扩展名 `.png` 或 `.jpg`。
- 已与用户确认：**保留左侧栏、右侧区域双视图切换**；封面写入**沿用配置目录授权（File System Access）**，不改 `server.py`。

## 三、方案总览

- 在 `.layout` 右侧增加第二个视图容器 `#homeView`，与 `.workspace` 二选一显示；左侧栏始终可见。
- 新增应用专属模块：
  - `js/covers.js`：封面索引、URL 解析、写入/改名。
  - `js/ui/home.js`：首页分组渲染与视图切换。
- 封面索引来源优先级：
  1. `state.toolsDirHandle` 已授权 → 遍历句柄中的 `*.png|jpg`，用 `URL.createObjectURL` 展示（即使授权目录不在服务器 tools/ 下也能显示）。
  2. 否则 HTTP 模式 → `fetch("tools/")` 解析目录列表，用相对 URL 展示。
  3. 仍失败 → 按约定路径 `tools/<基名>.png` 兜底，`<img>` 加载失败后尝试 `.jpg`，再退化为图标占位。
- 封面上传入口放在「配置工具」弹窗；保存工具后按最终工具名写入，改名时同步重命名封面文件。
- 不修改 `server.py`、不改动 API/运行流程。

## 四、详细改动

### 1. `index.html`

- 顶栏按钮组新增：
  ```html
  <button class="key-btn" id="homeBtn">🏠 工具首页</button>
  ```
- 在 `.workspace` 之前插入首页视图（工作区初始内联 `display:none`，避免启动闪一下工作页）：
  ```html
  <div class="home-view" id="homeView">
    <div class="home-head">
      <div>
        <h2>工具首页</h2>
        <p>按分类浏览全部工具，点击封面进入工作页</p>
      </div>
    </div>
    <div id="homeGrid"></div>
  </div>
  ```
- 工具配置弹窗（`#toolModal`）在「图标 / 名称 / 实例类型」行之后新增封面编辑区：
  - `#coverPreview`：180×112 预览框，无图时显示「暂无封面」。
  - `#coverPickBtn`：选择图片按钮。
  - `#coverHint`：说明「保存在 tools/工具名.png|jpg，支持 PNG/JPG，≤8MB，建议 16:10」。
  - `#coverFileInput`：`accept="image/png,image/jpeg"`，隐藏。

### 2. 新增 `js/covers.js`（应用专属）

导出（均使用 `state.toolsDirHandle` 与 `toolsDirGranted()`）：

- `refreshCoverIndex()`：重建索引 `Map<基名小写, {name, url, objectUrl?}>`。
  - 已授权句柄：`for await (const [name, handle] of dh.entries())` 过滤 `\.(png|jpe?g)$`，`URL.createObjectURL(await handle.getFile())`。
  - 未授权且 `location.protocol` 为 http：`fetch("tools/")`，正则提取 `href`，解码后过滤图片，URL 用 `tools/ + encodeURIComponent(name)`。
  - 重建前 `URL.revokeObjectURL` 旧索引中的 object URL；用递增序号防止并发刷新互相覆盖。
- `coverUrlFor(toolName)`：按 `toolBaseName({name})` 小写查索引；未命中时在 HTTP 模式返回 `tools/<encodeURIComponent(基名)>.png` 作为兜底候选，否则返回 `null`。
- `saveCover(toolName, file)`：
  - 未授权 → 抛出「请先授权 tools 配置目录（左侧 🗂 配置目录）再上传封面」。
  - 仅接受 `image/png` → `.png`、`image/jpeg` → `.jpg`；大小 ≤ 8MB。
  - 先删除同基名的另一种扩展名旧文件，再写目标文件；更新索引并返回文件名。
- `renameCover(oldToolName, newToolName)`：基名变化时，读取旧 `.png/.jpg` → 写入新基名 → 删除旧文件；无封面则静默返回。
- 不做自动删除孤立封面（见「假设与边界」）。

### 3. 新增 `js/ui/home.js`（应用专属）

- `renderHome(renderAll)`：缓存 `renderAll` 回调，按与侧栏一致的规则分组（`tagsOf` + 未分类最后 + 中文排序），每组渲染标题 + 卡片网格；无工具时显示空状态。
- 卡片结构（DOM 构建，文本用 `textContent` 防注入）：
  - 封面区：`coverUrlFor(t)` 有值则 `<img loading="lazy">`，`onerror` 先尝试 `.jpg` 再替换为图标占位（渐变底 + `t.icon`）。
  - 信息区：名称、两行截断描述、状态角标（生成中 / 最近完成 / 已配置 / 待配置，判定逻辑同侧栏 `statusOf`）。
  - 点击卡片：先把当前 `resultArea.innerHTML` 存入 `state.toolResults[state.activeId]`，再设置 `state.activeId`、`saveActiveId()`、`renderAll()`、`showWorkView()`。
- `showHomeView()`：切换到首页 → `applyView()` → `await refreshCoverIndex()` → `renderHome()`。
- `showWorkView()`：切换到工作页 → `applyView()`。
- `applyView()`：切换 `#homeView` / `.workspace` 的显示，并更新 `#homeBtn` 的选中样式。
- 首页状态角标在进入首页时重绘，因此运行中返回首页能看到「生成中」；停留在首页期间不额外轮询刷新。

### 4. `js/main.js`

- 引入 `renderHome, showHomeView, showWorkView`。
- `renderAll()` 增加 `renderHome()`：
  ```js
  function renderAll() { renderToolList(renderAll); renderWorkspace(); renderHome(); }
  ```
- 绑定 `#homeBtn` → `showHomeView()`。
- 给 `#toolList` 增加事件委托：`e.target.closest(".tool-item")` 时调用 `showWorkView()`（分类头的展开/收起不触发）。用于从首页通过左侧列表切换工具后自动进入工作页。
- 启动流程末尾：`renderAll(); showHomeView();`，保证默认进入首页。
- 不修改 API Key、目录授权、重置缓存等既有逻辑。

### 5. `js/ui/panels.js`（应用专属）

- 模块内保存暂存状态 `pendingCoverFile`。
- `initToolPanel()` 中绑定封面选择：
  - 点击 `#coverPickBtn` → `#coverFileInput.click()`。
  - `change` 时校验类型（PNG/JPG）与大小（≤8MB），生成 object URL 预览，记录待保存文件；清空 input 便于重复选择同一文件。
- `openTool(t)` 中重置暂存文件，并展示当前封面（`coverUrlFor(t.name)`）或「暂无封面」。
- 新增 `afterToolSave(tool, prevName)`（供 modal.js 调用）：
  - 有暂存文件 → `saveCover(tool.name, file)`，状态栏提示写入的文件名。
  - 否则若 `prevName !== tool.name` → `renameCover(prevName, tool.name)`，成功则提示。
  - 失败用 `showStatus(..., "error")` 提示，不阻断工具保存。
  - 完成后 `await refreshCoverIndex()`，调用 `renderHome()` 刷新卡片，再 `showWorkView()` 进入工作页（与原有「保存后选中该工具」体验一致）。

### 6. `js/ui/modal.js`（公共核心，向后兼容）

## 五、关键流程

### 启动
`renderAll()` 渲染侧栏/工作区/首页 → `showHomeView()` 刷新封面索引并重绘 → 显示首页。`state.activeId` 仍沿用上次选中值，只有点击卡片/左侧条目才进入工作页。

### 上传封面
配置工具 → 选择 PNG/JPG → 预览 → 保存工具 → modal 保存工具数据并 `renderAll` → `afterToolSave` 写入 `tools/<基名>.png|jpg` → 刷新索引、首页卡片、进入工作页。

### 工具改名
保存时 `writeToolToDir` 已有逻辑负责 JSON 改名；`afterToolSave` 读取旧封面内容写入新基名并删除旧文件。

### 视图切换
- 首页 → 卡片：选中工具并进入工作页。
- 首页 → 左侧条目：toollist 现有逻辑选中工具，main.js 委托监听进入工作页。
- 工作页 → 顶栏「🏠 工具首页」：返回首页并刷新封面。
- 首页点击分类头：只展开/收起，不跳转工作页。

## 六、命名与数据规则

- 工具配置文件名：`toolFileName(t)` = 非法字符 `[\\/:*?"<>|]` 替换为 `_`，中文保留，后缀 `.rhtool.json`。
- 封面文件名：`toolBaseName(t)` + `.png` 或 `.jpg`，与配置同基名、同目录。
- JPEG 上传统一存为 `.jpg`；PNG 存为 `.png`；其他格式拒绝并提示。
- 封面文件不写入 `.rhtool.json`，不改变现有配置格式，旧配置完全兼容。

## 七、假设与边界

- 首页采用「保留左侧栏 + 右侧双视图」，启动默认首页，不记忆上次视图。
- 封面写入依赖已授权的 `tools` 目录（用户已确认）；未授权时上传会提示先授权，与现有配置写入行为一致。
- 一个工具多个标签时在首页多个分类各出现一次，与左侧栏现状一致。
- 删除工具**不自动删除封面文件**（避免改动公共核心的删除逻辑）；残留封面不会显示在首页，可手动清理。
- 不新增搜索/筛选/拖动排序等未要求功能。
- 首页卡片不在运行期间实时刷新状态；进入首页或工具保存后会重绘。
- `modal.js` 的改动仅为可选钩子，保持 COMFYUI_api 同步兼容；`covers.js`、`home.js` 为 RunningHub 专属，加入公共同步列表前需另行评估。

## 八、验证步骤

1. `启动工具.bat` 启动 → 默认显示工具首页，右侧封面网格按分类分组，左侧栏可见。
2. 未设置封面的工具显示图标渐变占位，不出现破损图片。
3. 授权 tools 目录后，在配置弹窗上传 PNG → `tools/<工具名>.png` 生成，首页卡片立即显示；上传 JPG → 存为 `.jpg`。
4. 未授权 tools 目录时上传 → 提示先授权，工具本身仍可正常保存。
5. 修改工具名称并保存 → `.rhtool.json` 与封面文件同时改名；首页仍正常显示。
6. 点击首页卡片 → 进入工作页并选中对应工具；点击左侧条目 → 进入工作页；点击顶栏「🏠 工具首页」→ 回到首页。
7. 刷新页面 → 仍默认进入首页，封面正常加载（分别验证 HTTP 目录扫描与目录授权两种模式）。
8. 手工把 `工具名.png` 放入 `tools/`（不授权目录、仅 HTTP 模式）→ 首页能显示。
9. 多标签工具在多个分类中出现；无工具时显示空状态。
10. 回归检查：工具切换时结果隔离、生成/取消/自动下载、API Key、目录授权、重置缓存、导入配置、删除工具均与改动前一致。
