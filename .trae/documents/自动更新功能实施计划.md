# 自动更新 + sys_tools/user_tools 分离 实施计划

## 一、目标

1. **工具配置按来源分离**：安装目录的 `sys_tools/` 由开发者维护，程序更新时整体覆盖；用户自建/复制/导入的工具放在 `data/user_tools/`，永远不被更新影响。
2. **唯一身份证**：工具以 `webappId` 识别，用户改名、改文件名都不影响匹配。
3. **删除不复活**：用户删除系统工具时在 user_tools 写墓碑，更新/重置后仍保持删除。
4. **重置系统工具**：安装目录附带 `sys_tools.zip`，一键恢复系统工具（清墓碑、备份旧目录）。
5. **自动更新**：检查 → Gitee 优先/GitHub 回退下载 → SHA256 校验 → 静默覆盖安装 → 自动重启；启动时静默检查。

---

## 二、目录与身份模型

| 位置 | 内容 | 维护者 |
|---|---|---|
| `{app}\sys_tools\`（源码即仓库 `sys_tools/`） | 系统工具配置 + 系统封面 | 开发者，更新时整体覆盖 |
| `{app}\sys_tools.zip` | sys_tools 打包副本，打包脚本自动生成 | 开发者，用于重置 |
| `%LOCALAPPDATA%\RunningHubToolbox\data\user_tools\` | 用户配置 + 用户封面 | 用户 |
| `data\user_tools\.deleted.json` | 系统工具墓碑：`{"webappIds": [...]}` | 程序写入 |
| `data\backup\` | 迁移/重置前备份 | 程序写入 |

**合并规则**

- 加载顺序：user_tools 优先。同 `webappId` 时隐藏 sys 原版；user 内同 ID 多份（V1/V2 变体）全部显示。
- 墓碑中的 `webappId` 不显示，更新后也不复活。
- sys_tools 内 `webappId` 必须唯一；user_tools 允许重复。

**编辑规则**

- 修改系统工具 → 直接写回 `sys_tools`；界面提示「系统工具的修改会在程序更新时被覆盖，可复制为我的工具」；`sys_tools` 不可写时自动转存为 user_tools 副本并提示。
- 「复制为我的工具」→ 把当前生效配置+封面复制到 user_tools（文件名冲突时追加「 (我的)」），之后编辑与更新互不影响。
- 新建 / 导入 → 一律写 user_tools。
- 系统工具移入回收站/永久删除 → 写墓碑并隐藏（不删 sys 文件）；「重置系统工具」清空墓碑，使其重新出现。用户工具的回收站沿用现有 `deleted:true` 逻辑。

## 三、后端改造（server.py）

### 3.1 目录与常量

```python
SYS_TOOLS_DIR = os.path.join(BASE, "sys_tools")          # 不存在时等同于禁用系统工具
USER_TOOLS_DIR = os.path.join(DATA_DIR, "user_tools")
TOMBSTONE_FILE = os.path.join(USER_TOOLS_DIR, ".deleted.json")
SYS_ZIP = os.path.join(BASE, "sys_tools.zip")
```

- 新增 `_sys_tools_dir()`、`_user_tools_dir()`（均 `makedirs(exist_ok=True)`）。
- 保留 `_tools_dir()` 仅为兼容旧调用，内部改为返回 `_user_tools_dir()`；所有新逻辑显式区分来源。
- 删除 `_tools_dir()` 依赖 appinfo 第一行的行为：`appinfo.txt` 首行继续写入（兼容旧文件），但工具路径不再由它决定。

### 3.2 读取合并（前端扫描接口）

新增 `GET /tools-index`（Host 校验即可）返回：

```json
{
  "ok": true,
  "files": [
    {"file": "KLEIN-单图编辑（可绘蒙版）.rhtool.json", "source": "sys", "webappId": "...", "name": "...", "cover": "同名.png"}
  ],
  "deleted": ["webappId1"]
}
```

- 扫描两个目录的 `*.rhtool.json`，解析出 `webappId/name`；解析失败的文件仍返回但 `broken:true`。
- 按 3.1 规则去重：墓碑剔除；user 与 sys 同 ID 时只保留 user。
- 封面按配置基名查找 `.png/.jpg/.jpeg/.webp`，user 优先。
- `/tools/` 静态路由改为合并视图：同 ID 只暴露生效的那一份；文件名冲突时 user 优先；拒绝路径穿越的逻辑保持不变。

### 3.3 保存 / 删除 / 封面

改造现有处理方法，增加 `source` 字段：

- `POST /save-tool`：入参增加 `source: "sys"|"user"`（缺省 `user`）。
  - `sys` → 写 `SYS_TOOLS_DIR`；不可写（`PermissionError/OSError`）→ 改写 `USER_TOOLS_DIR`，响应 `{"ok":true, "source":"user", "downgraded":true}`。
  - 改名时只清理**同目录**的旧文件；`_remove_duplicate_tools` 限定在同目录内执行，绝不删除另一目录的文件。
  - 保存 user 工具不影响 sys 原版（由加载规则隐藏）。
- `POST /delete-tool`：入参增加 `source`。
  - `sys` → 不删 sys 文件，改为向墓碑写入 `webappId`；若配置缺失 webappId，则退回直接删除 sys 文件（更新后可恢复）。
  - `user` → 现有逻辑（删配置与同名封面）。
- `POST /tool-tombstone`：`{webappId, deleted:true|false}` 增删墓碑，供回收站/还原使用。
- `POST /copy-tool`：`{file}`（sys 配置文件名）→ 读取配置与封面 → 写入 user_tools（同名存在时文件名追加「 (我的)」「 (我的 2)」…，返回新文件名与 source）。
- `POST /reset-sys-tools`（令牌校验）：
  1. 校验 `SYS_ZIP` 存在且为合法 zip；
  2. 备份 `SYS_TOOLS_DIR` 到 `data\backup\sys-YYYYmmdd_HHMMSS`；
  3. 清空 sys_tools 下 `*.rhtool.json` 与封面扩展名文件（含被改名的残留）；
  4. 解压 zip 到 sys_tools（防路径穿越：拒绝绝对路径与 `..`）；
  5. 清空墓碑文件；
  6. 返回 `{"ok":true,"restored":n}`。
- `POST /save-cover` / `POST /rename-cover`：增加 `source`，分别作用于两个目录；user 封面优先展示。
- 静态封面路由同样按来源查找。

### 3.4 旧数据迁移（launcher.py，frozen 模式）

在 `ensure_dirs()` 之后新增 `migrate_legacy_tools()`：

1. 若 `DATA/tools` 不存在或为空 → 直接返回，写状态 `data\.migrated_sys_tools` 记录已迁移。
2. 把整个旧目录移动到 `data\backup\tools-<时间戳>`（`os.replace`，失败则复制后保留）。
3. 遍历备份里的每个配置：
   - `webappId` 在系统工具集合中 → 丢弃（系统副本身份，由新版 sys_tools 接管）；若原配置 `deleted:true` → 写入墓碑。
   - 否则 → 复制到 `user_tools`（连同同名封面），保留 `deleted:true` 状态。
4. 迁移完成后写入状态文件，后续启动不再重复执行。
5. 全部异常写 `启动日志.log`，绝不阻塞启动。

### 3.5 首次安装

`ensure_dirs()` 不再复制任何模板到 data：只创建 `user_tools`、`download`、`appinfo.txt`（内容保留两行格式）。系统工具直接读安装目录 `sys_tools`。

## 四、launcher.py 其他改动

### 4.1 更新安装钩子

```python
def perform_update(installer_path):
    log("开始自动更新：" + installer_path)
    close_app_windows()
    stop_tray()
    time.sleep(0.3)
    subprocess.Popen([installer_path, "/VERYSILENT", "/SUPPRESSMSGBOXES", "/NORESTART", "/SP-"], close_fds=True)
    os._exit(0)
```

`main()` 中注入 `server.UPDATE_INSTALL_HOOK = perform_update`。

## 五、前端改造

### 5.1 扫描与持久化（js/tools.js、js/store.js）

- `scanToolsDir()` 改为请求 `GET /tools-index`（JSON），不再解析目录 HTML：
  - 每个条目带 `{file, source, webappId, name}`；`state.tools` 中保存 `source`；
  - `state.toolFileNames[id] = file`；新增 `state.toolSources[id] = source`；
  - 墓碑 ID 直接跳过；`broken:true` 的文件给出损坏提示。
- `toolToConfigJSON()` 不写入 source（来源属于运行时状态）。
- `persistTool(t)` 发送 `{file, oldFile, source, content}`；响应 `source` 可能与请求不同（sys 不可写降级），同步回 `state.toolSources`。
- `removeToolFile(tool)` 发送 `{file, source}`。
- 新增导出：
  - `copyToolToUser(tool)` → `POST /copy-tool`，成功后重新扫描并选中新工具；
  - `resetSysTools()` → `POST /reset-sys-tools`，成功后 `resetToolsCache()` 重扫。
- 目录授权旧分支（File System Access API）保留但不再作为主路径；`toolsDirGranted` 相关代码可继续存在，避免大改。

### 5.2 工具列表交互（js/ui/toollist.js、js/ui/home.js、js/ui/modal.js）

- 工具条目显示来源：系统工具加小标识「系统」（`title` 说明随更新覆盖）；用户工具不显示或显示「我的」。
- 右键/悬浮菜单新增：
  - 系统工具：「复制为我的工具」；
  - 设置入口附近新增全局「重置系统工具」按钮（放在左侧列表底部或设置弹窗内）。
- 回收站逻辑按 source 分流：
  - `trashTool`：sys → `POST /tool-tombstone {deleted:true}`；user → 现有 `deleted:true` 配置保存逻辑。
  - 还原：sys → `POST /tool-tombstone {deleted:false}`；user → 现有逻辑。
  - 永久删除：sys → 确认后同样写墓碑（文件留在 sys_tools，更新可恢复）；user → 现有删除。
- 保存系统工具成功后，首次提示「系统工具的修改会在程序更新时被覆盖，可复制为我的工具」（同会话只提示一次）。

### 5.3 检查更新 UI（index.html、js/update.js、css/style.css、js/main.js）

- 顶栏 `#setupBtn` 后新增 `#checkUpdateBtn`（默认隐藏，HTTP 模式显示）。
- 新增 `#updateModal`（沿用 `.modal-mask/.modal/.modal-actions`）：当前/最新版本、更新说明滚动区、进度条、状态文字、按钮「立即更新 / 手动下载 / 取消 / 稍后」。
- `js/update.js`：`initUpdate()` 在 `main.js` 中调用：
  - 启动静默检查（失败静默）；有新版时按钮显示「有新版本 vX.Y.Z」。
  - 点击立即更新 → `POST /update/download` → 每 500ms `GET /update/progress` → `ready` 后 3 秒倒计时（可取消）→ `POST /update/install`。
  - `error` 时展示原因与「手动下载」（`/open-url` 打开发布页）。
- CSS：`.update-available`、`.update-bar`、`.update-bar-fill`、`.update-meta`、`.update-notes`。

## 六、自动更新后端（server.py）

### 6.1 清单与状态

```python
UPDATE_MANIFEST_URLS = [
    "https://gitee.com/jita45927/runninghub_api/raw/master/update/latest.json",
    "https://raw.githubusercontent.com/jita45927/runninghub_api/master/update/latest.json",
]
UPDATE_ALLOWED_HOSTS = {"gitee.com", "raw.githubusercontent.com", "github.com",
                        "objects.githubusercontent.com", "github-releases.githubusercontent.com"}
UPDATE_DIR = os.path.join(DATA_DIR, "update")
UPDATE_FILE_NAME = "RunningHubToolbox-update.exe"
UPDATE_INSTALL_HOOK = None
```

清单格式：

```json
{"app":"runninghub","version":"1.0.2","date":"2026-11-23","notes":"...",
 "installer":{"name":"RunningHub-AI-Toolbox-Setup-1.0.2.exe","size":16826867,
 "sha256":"...","urls":["gitee 地址","github 地址"]}}
```

### 6.2 接口

| 路由 | 方法 | 鉴权 | 行为 |
|---|---|---|---|
| `/update/check` | POST | 令牌 | 拉清单（10 秒超时、按序回退）、比较版本，返回当前/最新/说明/大小/发布页 |
| `/update/download` | POST | 令牌 | 后台线程下载（Gitee→GitHub），校验大小与 SHA256，失败换源 |
| `/update/progress` | GET | Host | 返回 `state/received/total/percent/source/error` |
| `/update/cancel` | POST | 令牌 | 取消并删除 `.part` |
| `/update/install` | POST | 令牌 | 再次校验 → 先回 `{ok}` → 调用 `UPDATE_INSTALL_HOOK`（未注入时内部兜底） |

安全：仅 https、主机白名单（含重定向终点）、固定落盘路径、版本比较用 `_version_key()`。

## 八、测试

### T1 目录合并（后端，临时目录）

1. 仅 sys 有工具 → 列表显示 sys。
2. user 复制同 ID → 只显示 user 一份。
3. user 同 ID 两份 → 显示两份，sys 隐藏。
4. 墓碑中的 ID → 不显示；`deleted:false` 后恢复。
5. 配置损坏 → 仍返回且标记 broken，其余正常。
6. 路径穿越、非法扩展名、跨目录访问 → 拒绝。

### T2 写入与编辑

1. 编辑 sys 工具 → 写入 sys_tools；连续启动/刷新不丢。
2. sys 目录设为只读 → 保存自动降级为 user_tools 副本，响应 `downgraded:true`。
3. 编辑 user 工具 → 只改 user_tools，sys 原版字节不变。
4. 改名 → 仅同目录旧文件被清理，另一目录无变化。
5. 「复制为我的工具」→ user_tools 出现副本；同名冲突自动加后缀；封面一并复制。

### T3 删除 / 回收站 / 墓碑

1. 删除 sys 工具 → 墓碑写入、列表隐藏、sys 文件仍在。
2. 重启 + 模拟更新替换 sys_tools → 仍隐藏（不复活）。
3. 还原 → 墓碑移除、工具重现。
4. 「重置系统工具」→ 墓碑清空、全部系统工具重现、sys 目录内容与 zip 一致、备份目录存在。
5. 删除 user 工具 / 清空回收站 → 现有行为不变。

### T4 迁移

1. 构造旧 `data/tools`：含系统工具副本（未改/改名）、用户自建、`deleted:true` 条目、封面。
2. 启动迁移 → 备份目录完整；系统副本被丢弃；自建工具与封面进入 user_tools；墓碑正确生成；状态文件写入。
3. 再次启动 → 不重复迁移、不重复备份。
4. 旧目录被移走后，列表只显示 sys + 迁移后的 user。

### T5 更新链路

1. mock 清单：有/无新版判断、版本比较（1.0.9 < 1.0.10）。
2. mock 下载：正常；首个源 404；首个源 SHA256 错误；首个源超时（10.255.255.1）；取消下载清理 `.part`。
3. 非白名单主机 / http 地址 → 拒绝。
4. 真机联测（先备份 data）：1.0.1 安装版收到 1.0.2 清单 → 自动下载 → 校验 → 窗口关闭 → 静默安装 → 自动重启 → 版本号更新；`user_tools`、墓碑、`download` 均保留；系统工具已整体换新（含被用户改过参数/改名的不留残留）。
5. 静默安装过程无向导界面；更新期间重复双击不产生双实例。

### T6 回归

- 新建/导入/导出/封面/排序/分类/回收站（用户工具）行为不变。
- `/appinfo`、`/shutdown`、`/show-window`、单实例、托盘退出正常。
- `python -m py_compile server.py launcher.py`；浏览器控制台无报错。
- `sys_tools.zip` 内容与 `sys_tools/` 逐文件一致（打包后校验）。

## 九、决策与假设

- 唯一键 `webappId`；sys 内唯一，user 允许变体。
- 系统工具修改可写回 sys，更新即覆盖，不承诺保留；长期保留走「复制为我的工具」。
- 删除系统工具写墓碑；重置系统工具会清墓碑。
- 首次升级迁移规则：sys 内已存在的 ID 丢弃旧副本，其余进 user_tools，旧目录整体备份。
- 版本：本次发布 1.0.2，`APP_VERSION` 为唯一来源。
- Gitee 匿名下载需发布前实测；不可行则退化为 raw 文件或仅 GitHub。
- 本期不改 COMFYUI 项目，完成后按 `sync-core.ps1` 同步公共前端（`js/update.js` 加入清单）。

## 十、风险

- 安装包未签名，静默安装可能被杀毒软件拦一次；需在文档说明。
- sys_tools 放在安装目录，若被手动挪到 Program Files 会不可写 → 已有降级逻辑。
- Gitee 平台策略变化 → 清单内可随时换源，无需发新版。
- 迁移涉及用户数据 → 全部先备份，失败不阻塞启动。
