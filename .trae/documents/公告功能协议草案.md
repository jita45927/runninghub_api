# 公众号公告功能 · 协议草案 v0.1

> 状态：已实现（v0.1）。适用范围：RunningHub AI 设计师工具箱（本地服务 + 浏览器窗口）。

## 1. 目标与非目标

目标：用户打开工具时，能看到公众号最新文章的提醒，并可一键跳转阅读。

非目标：

- 不做微信消息推送（个人订阅号没有该能力）。
- 不做用户账号体系，不统计阅读量、不上报任何用户信息。
- 不自动弹窗打断生成任务。

## 2. 总体链路

```
公众号发文 → 更新 announcement.json（release 分支）
          → 本地 server.py 多源拉取（域名白名单）
          → 前端比对已读记录 → 顶部角标 / 公告列表
          → 系统浏览器打开文章
```

客户端不直连微信，也不直连第三方静态源：由本地服务代理拉取，沿用自动更新现有的多源与白名单机制。

## 3. 清单文件协议

### 3.1 位置与多源

文件：`release` 分支 `/update/announcement.json`，与 `latest.json` 同目录。

拉取顺序（失败自动切下一个）：

1. `https://gitee.com/matt8469/runninghub_api/raw/release/update/announcement.json`
2. `https://cdn.jsdelivr.net/gh/jita45927/runninghub_api@release/update/announcement.json`
3. `https://raw.githubusercontent.com/jita45927/runninghub_api/release/update/announcement.json`

### 3.2 数据结构

```json
{
  "schema": 1,
  "updatedAt": "2026-11-26T16:00:00+08:00",
  "items": [
    {
      "id": "20261126-seedvr2",
      "title": "SeedVR2 工作流更新说明",
      "summary": "一句话摘要，列表内展示",
      "url": "https://mp.weixin.qq.com/s/xxxx",
      "publishedAt": "2026-11-26"
    }
  ]
}
```

### 3.3 字段约束

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `schema` | int | 是 | 固定为 `1`，用于未来升级 |
| `updatedAt` | string | 是 | ISO 8601 时间 |
| `items` | array | 是 | 最多 20 条，按 `publishedAt` 倒序 |
| `items[].id` | string | 是 | 全局唯一且稳定，建议 `日期-短名`，≤ 64 字符 |
| `items[].title` | string | 是 | ≤ 40 字 |
| `items[].summary` | string | 否 | ≤ 80 字，纯文本 |
| `items[].url` | string | 是 | 必须 `https://mp.weixin.qq.com/` 开头 |
| `items[].publishedAt` | string | 是 | `YYYY-MM-DD` |

容错规则：未知字段忽略；单条缺必填字段或 URL 非法时只丢弃该条，不影响整份清单；整份 JSON 非法视为「无公告」。

## 4. 本地服务接口

`POST /announcement/check`

- 无请求参数，不接收任何用户数据。
- 复用 `UPDATE_MANIFEST_URLS` 同域白名单校验（`_validate_update_url`），超时 10 秒。
- 成功返回：`{ "ok": true, "updatedAt": "...", "items": [ ... ] }`
- 失败返回：`{ "ok": false, "error": "..." }`
- 建议加 5 分钟内存缓存，避免前端重复请求；不落盘、不写日志中的链接参数。
- 不使用 API Key，不访问 RunningHub 接口。

## 5. 客户端行为

### 5.1 检查时机

- 程序启动后延迟 3 秒检查一次。
- 页面处于打开状态时，每 3 小时检查一次。
- 不做后台常驻轮询；托盘运行且窗口关闭时不检查。

### 5.2 失败策略

- 任何异常（断网、404、JSON 损坏、超时）均静默处理，不弹提示、不写红色错误。
- 不自动重试风暴；下一次定时检查再试。

### 5.3 已读状态

- localStorage 键：`rh_ann_seen_v1`。
- 结构：`{ "seenIds": ["..."] }`，最多保留 200 个 id，超出按时间淘汰最旧。
- 首次成功拉取（本地无该键）：把当前全部 id 直接写入 `seenIds`，视为已读，避免新装用户被"历史未读"轰炸。
- 未读数 = 清单中不在 `seenIds` 的条目数。
- 卸载重装或清缓存后会重新基线一次，属于可接受行为。

## 6. 界面交互

- 入口：顶部推广条「微信公众号二维码」按钮（`promoQrBtn`）旁边新增「📢 公告」按钮。
- 有未读时：按钮显示红点 + 未读数字；无未读时仅显示图标。
- 点击打开公告弹窗，复用现有 modal 样式，列表展示标题、日期、摘要。
- 点击某条：立即记为已读，并通过系统浏览器打开文章（`target="_blank"`）。
- 弹窗内提供「全部标为已读」按钮；打开弹窗本身不自动全读。
- 清单为空、拉取失败：不显示红点，按钮仍可打开空列表并提示「暂无公告」。
- 不自动弹窗、不覆盖结果区、不打断正在运行的任务。

## 7. 安全约束

- URL 必须同时满足：`https` 协议、host 严格等于 `mp.weixin.qq.com`；服务端校验一次，前端渲染前再校验一次。
- 标题、摘要统一用 `esc()` 转义后插入，禁止用原文拼接 `innerHTML`。
- 清单拉取不携带 API Key、机器码或任何本地路径。
- 前端只调用本地接口，不直接跨域访问第三方静态源。
- 公告链接一律由系统默认浏览器打开，不在应用窗口内跳转。

## 8. 发布端流程（个人订阅号）

1. 公众号后台发文，复制文章链接。
2. 运行本地脚本（或手工编辑）填写标题、摘要、链接。
3. 脚本校验字段与 URL 白名单，生成 `id`（重复则拒绝），插入 `items` 头部。
4. 写入 `build/announcement.json`，执行发布时同步到 release 分支。
5. Gitee 与 GitHub 各推一份，jsDelivr 自动回源。

可选增强：脚本记录上次发布，重复执行同链接时提示已存在。

## 9. 兼容与回滚

- 老版本客户端不会请求该接口，完全不受影响。
- 清单缺失或格式错误时，客户端按「无公告」处理。
- 回滚方式：删除 `announcement.json` 即可，不影响自动更新和其他功能。
- `schema` 升级时新增字段保持向后兼容，老客户端忽略未知字段。

## 10. 验收标准

- 发布新文章后，最迟一次定时检查或重启程序即可看到红点。
- 点击阅读后，重启程序不再提示同一条。
- 断网、清单 404、JSON 损坏时无任何错误提示。
- 非 `mp.weixin.qq.com` 的链接不会出现在列表中。
- 老版本程序与自动更新功能不受影响。

## 11. 已确认项

- 列表不显示文章封面图。
- 不做系统托盘气泡提醒。
- 检查间隔 3 小时。
- 「公告」按钮放在推广条「微信公众号二维码」按钮旁边。
