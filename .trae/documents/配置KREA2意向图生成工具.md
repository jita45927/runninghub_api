# 配置 KREA2 意向图生成工具

## Context

用户提供 RunningHub ComfyUI 工作流 `2121201215919972354` 及导出的 `KREA2意向图生成-根据图片_api.json`，要求将其配置为当前程序可直接使用的新工具。现有表单渲染、图片上传、任务创建与结果下载逻辑均可复用，因此只需新增一份工具配置，不修改业务代码，也不同步其他项目。

## 实施方案

新增 `tools/KREA2意向图生成-根据图片.rhtool.json`，沿用现有 `runninghub-tool-config` v1 格式：

- 名称：`KREA2意向图生成-根据图片`
- 类型：`workflow`，工作流 ID：`2121201215919972354`
- 实例：`default`
- 标签：`意向图生成`
- 原始地址：留空，不猜测工作流页面 URL
- 说明：上传参考图，按用户指令生成 KREA2 写实意向图，可调整比例、分辨率和随机种子

根据上传的工作流 JSON 配置 5 个输入项：

| 输入项 | 类型 | 节点与字段 | 默认值 |
|---|---|---|---|
| 上传参考图 | `image` | `643.image` | 空，要求用户上传，不沿用导出文件中的示例图片 |
| 用户指令 | `textarea` | `658.text` | `写实照片，增加人，慢门摄影，行人，增强商业氛围` |
| 出图比例 | `select` | `74.aspect_ratio` | 默认 `16:9 (Widescreen)`，并复用现有 ResolutionSelector 的完整比例候选值 |
| 出图分辨率（百万像素） | `number` | `74.megapixels` | `2` |
| 随机种子 | `number` | `2.seed` | `1047999148699382` |

其余节点参数保持工作流默认值：不暴露 `multiple`、采样步数、CFG、系统提示词和 QwenVL 预设，避免破坏固定提示词结构及尺寸对齐约束。

## 复用与边界

- 复用 `js/ui/form.js` 的动态表单渲染、`js/runner.js` 的图片上传和 `nodeInfoList` 组装、`js/api.js` 的 `createTask` 工作流端点选择。
- 不修改 `js/api.js`：`addMetadata` 与 `usePersonalQueue` 不是该工具表单字段，现有任务创建请求无需为它们增加单工具特判。
- 不修改其他工具配置，不同步 `D:\project\COMFYUI_api`，不提交或推送 Git。

## 验证

1. 用 Python 分别解析新配置和用户上传的 `_api.json`，确认 JSON 合法、工具类型和 ID 正确，5 个 `(nodeId, fieldName)` 均存在，文本、比例、百万像素与种子默认值和源工作流一致。
2. 通过现有 `启动工具.bat` 启动本地程序并重新扫描 `tools/`，确认新工具出现在“意向图生成”分组，5 个输入项正确显示，默认比例为 `16:9 (Widescreen)`。
3. 检查图片选择/预览及参数输入；不提交真实生成任务，避免产生 API 费用。
