# RunningHub 工具自动配置

把用户提供的工作流导出文件、API 调用示例、curl、应用 ID 和补充说明转换为项目可直接加载的工具配置。资料足够时直接完成文件修改与验证，不只返回示例或操作说明。

## 1. 确认资料与边界

1. 读取用户上传的全部相关文件；附件保持只读，不修改原始 `_api.json`。
2. 从资料中提取工具名称、ID、工具类型、实例类型、原始地址、节点参数和用户指定分类。
3. 仅在缺少必要信息且无法从资料推断时提问，一次问清；不要询问已经提供的名称、ID 或字段。
4. 本 Skill 只维护当前 `runninghub_api` 项目。不要同步或复制配置到 `COMFYUI_api`，除非用户另行明确要求同步功能。

## 2. 先核对当前项目实现

修改前针对相关符号读取以下文件，避免依赖旧记忆：

- `js/config.js`：`FIELD_TYPES`、`ICON_OPTIONS`。
- `js/tools.js`：配置持久化格式、文件名规则、目录扫描及去重逻辑。
- `js/api.js`：`createTask` 的端点选择和 `enrichSelectOptions` 的下拉补全能力。
- `js/runner.js`：图片上传及 `nodeInfoList` 组装方式。
- `js/ui/form.js`：字段类型和 `def` 的实际渲染规则。
- `tools/` 中一至三个最相似的 `.rhtool.json`，复用命名、描述、标签和字段顺序习惯。

检查现有变更，只修改目标工具配置，不覆盖用户正在进行的其他修改。

## 3. 解析 RunningHub 资料

### 3.1 工具类型与 ID

| 资料中的端点或对象 | `toolType` | `webappId` 来源 |
|---|---|---|
| `/openapi/v2/run/workflow/{id}` | `workflow` | URL 末尾的 workflowId |
| `/openapi/v2/run/ai-app/{id}` | `app` | URL 末尾的 webappId |
| RunningHub AI 应用 API 调用资料 | `app` | 应用 API 资料中的 webappId |

- ID 始终保存为字符串，避免长整数精度损失。
- `instanceType` 默认使用资料值；未提供时为 `default`。
- `addMetadata`、`usePersonalQueue` 是请求级选项，不是节点字段，不加入 `fields`，也不要为单个工具给 `createTask` 加特判。
- curl 中空的 `nodeInfoList` 不代表工作流一定零参数；结合导出 JSON 判断必填输入。

### 3.2 节点来源

- ComfyUI `_api.json` 通常是 `{nodeId: {inputs, class_type, _title}}` 对象。节点 ID 使用对象键，`fieldName` 使用 `inputs` 的键，默认值取对应输入值。
- 如果资料已经包含 `nodeInfoList`，直接读取其中的 `nodeId`、`fieldName`、`fieldValue`，并用 `fieldData` 辅助识别下拉候选值。
- 结合 `class_type`、`_title`、字段名和默认值判断语义，不只按字段名猜测。
- 用户明确指定的输入项和默认值优先；未明确指定的固定内部参数保持工作流默认值。

## 4. 选择并映射表单字段

默认暴露用户会主动调整的图片、主提示词、比例、分辨率、随机种子和业务开关。固定系统提示词、内部反推预设、尺寸对齐倍数、模型连接和其他内部编排参数默认不暴露，除非用户要求或资料明确将其标为输入。

| 节点输入语义 | `type` | `def` 规则 |
|---|---|---|
| `LoadImage.image` 或其他图片上传输入 | `image` | 始终为空字符串，不能沿用导出文件中的示例图片文件名 |
| 主提示词、长文本、多行文本 | `textarea` | 使用资料中的原始文本 |
| 短文本 | `text` | 使用资料中的原始文本 |
| 整数、小数、尺寸、种子 | `number` | 转为十进制字符串，大整数不得经过浮点数 |
| 布尔开关 | `select` | 当前默认值在前，候选值仅使用小写 `true`、`false` |
| 枚举选项 | `select` | 默认值在第一位，后接完整候选值，使用英文逗号分隔 |

字段规则：

- 每个字段包含 `label`、`type`、`nodeId`、`fieldName`、`def`；`nodeId` 和 `def` 按现有配置习惯写成字符串。
- `label` 使用简洁中文并体现用途，例如“上传参考图”“用户指令”“出图比例”；布尔或特殊种子在标签中说明行为。
- 字段顺序通常为图片、主提示词、主要生成参数、高级参数。
- 下拉候选值必须与节点完全一致并保留大小写。只有节点类型和字段语义均已确认一致时，才可复用现有工具的候选列表。
- 无法取得完整候选列表时只填已确认的单个默认值，不编造选项；现有应用会在首次成功运行后自动尝试补全。本 Skill 不为了补全选项而提交真实任务。
- 只有真正的零参数工具才使用空 `fields`。源工作流存在必填输入时，不得为了简化而提交空配置。

## 5. 新增或更新配置

### 5.1 顶层结构

```json
{
  "type": "runninghub-tool-config",
  "version": 1,
  "name": "工具名称",
  "icon": "从 ICON_OPTIONS 选择",
  "desc": "简要说明输入、用途和主要可调参数",
  "sourceUrl": "",
  "toolType": "workflow",
  "webappId": "字符串ID",
  "instanceType": "default",
  "tags": ["最匹配的现有分类"],
  "fields": []
}
```

- 工具名优先使用用户指定值，否则从上传文件名去除扩展名和末尾 `_api` 得到。相同模型但节点或参数版本不同，添加清晰的版本后缀。
- 配置文件为 `tools/<工具名>.rhtool.json`，文件名中的 `\\ / : * ? " < > |` 替换为 `_`。
- `tags` 优先复用 `tools/` 中最合适的现有分类；确无匹配时再创建新分类，不使用旧版 `category`。
- `sourceUrl` 仅填写用户提供的原始页面地址，否则留空，不猜测 URL。
- 新文件不手写运行时 `id`，由现有加载器生成；更新文件时保留仍需使用的已有扩展字段和回收站状态。

### 5.2 去重与改名

1. 写入前扫描全部 `tools/*.rhtool.json`，同时按 `webappId` 和工具名查找匹配项。
2. 同一 ID 或同名时更新已有配置，不创建第二份；用户明确提供的新资料优先，但保留未要求修改的 `sourceUrl`、图标、分类等现有设置。
3. 如果名称导致文件名变化，遵循 `js/tools.js` 与 `server.py` 的现有改名逻辑处理旧配置及对应封面，不能留下重复配置。
4. 出现多份匹配且无法确定目标时，不任意删除；向用户说明冲突并给出涉及文件。
5. 通常无需修改 JS 或 Python。只有现有通用能力确实不支持资料中的字段时才修改业务代码，并采用通用实现，禁止按工具 ID 写分支。

## 6. 验证但不产生生成费用

### 6.1 静态校验

使用 Python 标准库解析新配置及源文件，至少确认：

- JSON 可解析，顶层类型、版本、ID、工具类型、实例类型、标签和字段列表合法。
- 字段类型均属于 `FIELD_TYPES`，必填键完整，同一 `(nodeId, fieldName)` 不重复。
- 有源节点数据时，每个节点和输入字段均存在；文本、数字、布尔和默认下拉值与源资料一致。
- 图片字段默认值为空，布尔候选值是小写 `true` 或 `false`，长 ID 和种子没有精度变化。
- 同一 `webappId` 或工具名没有意外重复配置，文件中没有 API Key。

### 6.2 页面校验

1. 检查本地服务，默认地址为 `http://127.0.0.1:8900`，实际端口可能顺延至 `8900-8909`；不要重复启动已有实例。
2. 服务可用时使用浏览器重新加载工具目录。缓存未更新时使用界面现有“重置工具缓存”能力，该操作不应删除配置文件。
3. 选中目标工具，核对分类、名称、说明、字段数量与顺序、各默认值、下拉首项和图片上传区域。
4. 不上传付费任务、不点击“开始生成”、不读取或输出浏览器中的 API Key。
5. 服务不可用时只报告静态校验通过，并明确页面校验未执行；提示用户双击 `启动工具.bat`，不得声称界面已经验证。

## 7. 收尾

- 不修改无关工具、业务代码、用户附件或工作区其他变更。
- 不自动提交或推送 Git，不自动同步其他项目。
- 最终用可点击文件链接报告配置路径，并简要列出工具类型、ID、分类、已配置字段和验证结果。
- 默认明确说明“未提交真实生成任务”。只有用户明确要求实际运行时才可另行执行，并遵循其运行范围。
